# Spec — 2.2c Errance des serviteurs dans la zone de base
Item TODO : 2.2c Errance des serviteurs | Branche : feature/servant-wandering | Statut : cadrage

## Objectif
Un serviteur posé erre sans tâche dans la zone de base ; posé hors zone, il y retourne seul (GDD, « De la mort du soldat au serviteur assigné », point 5). Prépare l'item 2 (assignation), qui remplacera l'errance par une tâche.

## Choix techniques déjà tranchés (pour la spec à venir)
- Logique dans un `AServantAIController` dédié (pas de parent commun avec `AEnemyAIController`), sans Tick ni Behavior Tree/StateTree : un cycle piloté par timers et `OnMoveCompleted`. `Start/StopWandering` publics pour l'item 2.
- `AServant` (constructeur) : `AIControllerClass = AServantAIController`, `AutoPossessAI = PlacedInWorldOrSpawned`. Le défaut moteur `PlacedInWorld` ne possède **pas** un pion spawné (vérifié dans `Pawn.cpp`), donc `DoPlaceServant` donnerait un serviteur inerte.
- Cycle : zone (`GetBaseZone()` à chaque décision) → `GetRandomPointInZone` → `ProjectPointToNavigation` (au plus `MaxProjectionAttempts` essais, extent Z = `GetZoneExtent().Z` + marge) → `MoveToLocation` (destination déjà projetée) → pause aléatoire → recommence. Tout échec (pas de zone, zone invalide, projection ratée, `Failed`/`Aborted`) relance après `RetryDelay`, jamais dans la même frame.
- Hors zone (`IsPointInZone` faux) : même tirage, sans pause avant le départ.
- `Spooky_Spores.Build.cs` : ajout explicite de `NavigationSystem` (aujourd'hui seulement en dépendance transitive via `AIModule`). **Point chaud.**
- Tests sans NavMesh : monde de test comme `BaseZoneWorldSpec` (absence de zone, zone invalide, échec de projection → nouvel essai planifié, possession au spawn). Le NavMesh, la marche et la clôture se vérifient en PIE.
- API vérifiées dans le moteur local 5.8.3 : `UNavigationSystemV1::ProjectPointToNavigation(const FVector&, FNavLocation&, const FVector& Extent, const ANavigationData*, FSharedConstNavQueryFilter) const`, `AAIController::MoveToLocation(Dest, AcceptanceRadius, bStopOnOverlap, bUsePathfinding, bProjectDestinationToNavigation, bCanStrafe, FilterClass, bAllowPartialPath)`, `virtual OnMoveCompleted(FAIRequestID, const FPathFollowingResult&)`, `ReceiveMoveCompleted` (délégué BP).

## Challenge : contradiction avec la doc technique, section 11
L'ennemi a abandonné `MoveToLocation` (« NavMesh fragile, Anim Blueprint non alimenté »). Le TODO 2.2c revient au NavMesh, et c'est justifié : une errance en ligne droite bute sur les arbres et la clôture. Cause probable du glissement : `NavMovementProperties.bUseAccelerationForPaths` vaut `false` par défaut (`NavigationTypes.h`). L'accélération reste alors nulle, et un Anim Blueprint qui la teste ne lance pas la marche. Je le passerai à `true` dans `AServant`, puis vérification en PIE (Anim Blueprint Debugger). Ce choix est technique, je ne le pose pas comme question, mais il faut le savoir.

## Constat éditeur (lecture seule)
`Lvl_Principal.umap` contient `NavMeshBoundsVolume_1` et `RecastNavMesh-SoldierAgent` (un seul agent : rayon 34, hauteur 176). Il reste à vérifier en éditeur s'ils couvrent toute la base et si les arbres et la clôture découpent bien le NavMesh (touche P).

## Décision ouverte pour Timéo
**D1. Serviteur sans chemin vers la base.**
Problème : posé sur un rocher, derrière la clôture ou hors NavMesh, le serviteur n'a aucun chemin vers la zone. Le joueur ne peut pas le saisir. Sans règle, il reste bloqué pour toujours ou piétine contre la clôture, et le GDD promet « il y retourne automatiquement ».
→ Je propose : chemins partiels refusés (`bAllowPartialPath = false`, l'échec devient explicite). Après `MaxFailedReturnAttempts` (3) décisions consécutives prises hors zone sans y être entré, le serviteur est **téléporté** sur le point projeté dans la zone, avec un `Warning` dans le log. Alternatives écartées : rester bloqué en réessayant (serviteur perdu pour de bon) ; refuser la pose hors zone atteignable (modifie 2.2a et `DoPlaceServant`, hors périmètre).
→ Qu'en penses-tu ? Téléportation acceptable visuellement (un futur effet de fumée pourrait la masquer), ou préfères-tu une autre règle ?
